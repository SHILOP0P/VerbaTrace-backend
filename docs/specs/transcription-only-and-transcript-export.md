# Транскрипция без анализа и экспорт версий

## Загрузка и обработка

`POST /api/v1/calls` принимает multipart-поле `processing_mode`:

| Значение | Результат |
|---|---|
| `transcribe` | Транскрипция без автоматического анализа |
| `analyze` или отсутствие поля | Транскрипция и последующий анализ; совместимость с прежними клиентами |

Режим сохраняется в `calls.transcription_only` и возвращается в ответах звонка. Неизвестное значение отклоняется с HTTP 400. Одиночная и пакетная загрузки используют одинаковый контракт.

Обработчик не создаёт задание анализа для звонка с `transcription_only=true`, в том числе при повторной обработке уже завершённой транскрипции. SSE завершает поток на `transcribed`. Отдельный существующий запрос анализа остаётся доступным, а фронтенд обновляет ожидающий анализ до завершения.

Режим доступен на всех тарифах. Существующие лимиты, кредиты, правила доступа, политика защиты данных и тарифный вариант транскрибирования сохраняются. Отсутствие автоматического анализа означает отсутствие операции списания за анализ.

## Экспорт

`POST /api/v1/calls/{uuid}/reports` дополнительно принимает:

| Поле | Значения |
|---|---|
| `content` | `transcription` — только транскрипция; `full` или отсутствие — анализ и транскрипция |
| `transcription_revision` | Положительный номер версии; 0 или отсутствие — активная версия |

Транскрипционный экспорт доступен без готового анализа и без тарифного разрешения экспорта аналитики. Полный отчёт сохраняет прежнее требование готового анализа и разрешения тарифа. Доступ к звонку проверяется перед чтением содержимого.

Экспорт читает выбранный неизменяемый снимок, включая исправленные слова и спикеров. Исторические транскрипции без истории считаются версией 1. Неизвестная или неготовая версия отклоняется; подмена её текущим текстом не производится. Экспорт оригинальных персональных данных не добавляется.

Представление соответствует странице звонка: приоритет у слов, соседние слова одного спикера объединяются в реплики с временным диапазоном и именем из назначений спикеров. Без спикеров остаётся обычный текст. Если слов нет, используются сегменты, затем текст.

Поддерживаются PDF, DOCX, Markdown и XLSX. Отчёт без анализа не содержит разделов и метаданных анализа. В ответе `analysis_uuid` равен null. PDF поддерживает кириллицу, переносы страниц и нумерацию; Docker-образ содержит необходимый шрифт.

Ключ защиты от повторного создания включает звонок, формат, содержимое, версию транскрипции и анализ. Разные версии и варианты содержимого могут экспортироваться независимо. Уже созданные файлы являются снимками и автоматически не переписываются.

Содержимое экспорта запоминается в браузере; версия — отдельно для каждого звонка. Списки используют общий `SelectControl`. Отступ над плеером закреплён за обёрткой медиа, включая загрузку и защищённую запись.

## Обновление

Необходима миграция `202609070001_transcription_only_calls.sql` и обновление API вместе с фронтендом. Старый API игнорирует новое multipart-поле и продолжает автоматически анализировать загрузки.
